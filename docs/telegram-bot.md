# Бот Telegram-канала

Бот ведёт канал [@tenet_t7_dash](https://t.me/tenet_t7_dash):

- **анонсирует релизы** — после успешной сборки по тегу `v*` публикует пост
  из `CHANGELOG.md` со ссылкой на APK в GitHub Release;
- **публикует отложенные посты** из очереди `content/telegram/queue/`;
- **модерирует обсуждение** — удаляет спам, ограничивает и блокирует
  нарушителей, приветствует новичков, отвечает на `/help`, `/rules`, `/apk`,
  `/id`.

Всё работает на GitHub Actions, отдельный сервер не нужен. Код — в
`tools/telegram/`, только стандартная библиотека Python (ничего ставить не
надо).

## 1. Создать бота

1. Откройте [@BotFather](https://t.me/BotFather) в Telegram, отправьте
   `/newbot`.
2. Имя — например `Tenet T7 Dash`; username обязан заканчиваться на `bot` —
   например `tenet_t7_dash_bot`.
3. BotFather пришлёт **токен** вида `1234567890:AA...`. Это секрет: не
   коммитьте его и не пересылайте в чатах. Если токен утёк — `/revoke` в
   BotFather.

Отключите приватность, чтобы бот видел все сообщения в группе (для админа
это не обязательно, но так надёжнее):

```
/setprivacy → выбрать бота → Disable
```

После смены privacy бота нужно удалить из группы и добавить заново — иначе
настройка не применится.

## 2. Добавить бота в канал

1. Канал → «Управление» → «Администраторы» → «Добавить администратора» →
   найдите бота по username.
2. Включите право **«Публикация сообщений»** (остальное можно не давать).
3. Без прав администратора бот не сможет писать в канал.

## 3. Привязать чат обсуждений

Комментарии к постам живут в привязанной группе.

1. Канал → «Управление» → «Обсуждение» → создайте или привяжите группу
   (например `@tenet_t7_dash_chat`).
2. Добавьте бота в эту группу и сделайте **администратором** с правами:
   - «Удаление сообщений»,
   - «Блокировка участников».
3. Узнать ID группы:

   ```bash
   TG_BOT_TOKEN='1234567890:AA...' python3 tools/telegram/bot.py chats
   ```

   Напишите любое сообщение в группе, затем запустите команду. Она покажет
   `ID`, тип и название чатов из последних обновлений. Для публичной группы
   можно и так:

   ```bash
   TG_BOT_TOKEN='...' python3 tools/telegram/bot.py chat-id @tenet_t7_dash_chat
   ```

   ID группы выглядит как `-1001234567890` — его нужно указать в переменной
   репозитория (шаг 4).

## 4. Секреты и переменные репозитория

GitHub → репозиторий → **Settings → Secrets and variables → Actions**.

| Тип | Имя | Значение |
| --- | --- | --- |
| Secret | `TG_BOT_TOKEN` | токен из BotFather |
| Variable | `TG_CHANNEL_ID` | `@tenet_t7_dash` (можно не задавать — это значение по умолчанию) |
| Variable | `TG_DISCUSSION_CHAT_ID` | ID группы обсуждений, `-100...`. Без неё модерация выключена |

`GITHUB_TOKEN` для ссылки на APK подставляется автоматически.

## 5. Проверить

Actions → **Telegram: проверка** → Run workflow. Должно быть зелёным:

```
✅ Бот: @tenet_t7_dash_bot (id ...)
✅ Канал: ... (@tenet_t7_dash)
✅ Право публикации: есть
✅ Чат обсуждений: ...
✅ Удаление сообщений
✅ Блокировка участников
✅ Webhook выключен (getUpdates доступен)
```

Если что-то красное — смотрите раздел «Если не работает».

## 6. Анонсы релизов

Релиз собирается существующим workflow `.github/workflows/release.yml` по
тегу `v*`. После успешной публикации GitHub Release запускается
`.github/workflows/telegram-post.yml` и:

1. берёт раздел версии из `CHANGELOG.md` (для `v1.8-dev` — раздел `[1.8]`);
2. собирает пост в HTML Telegram: заголовок, дата, списки, ссылки, код;
3. обрезает слишком длинный текст по границе слова и добавляет ссылку на
   релиз (лимит сообщения — 4096 символов);
4. внизу поста — прямая ссылка на APK из релиза и ссылка на сам релиз; файл
   APK в канал не прикрепляется (при ручном запуске можно включить
   `attach_apk` — тогда APK до 49 МБ уходит отдельным сообщением);
5. для тега с `-dev` добавляет пометку «тестовая сборка».

Если раздела в CHANGELOG нет, текст берётся из описания GitHub Release. Если
нет и его — workflow падает с понятной ошибкой, но релиз уже опубликован.

Переопубликовать вручную: Actions → **Telegram: анонс релиза** → Run
workflow → тег (`v1.8.1`). Сначала можно поставить `dry_run` — текст
печатается в лог, ничего не отправляется. Учтите: повторный запуск создаст
второй пост в канале.

## 7. Отложенные посты

Положите файл `content/telegram/queue/имя.md`:

```markdown
---
publish_at: 2026-11-12T09:00:00+03:00
photo: docs/screenshots/dashboard.png
---
Вышел **DashHeadUnit 1.8**. Что нового — в [релизе](https://github.com/igor-kim0/dash_t7/releases/tag/v1.8).

- пункт;
- ещё пункт.
```

- `publish_at` — обязательное время с часовым поясом (`+03:00` или `Z`).
  Без пояса считается UTC.
- `photo` — необязательный путь к картинке **от корня репозитория**; если
  текст длиннее подписи Telegram (~1000 символов), фото уйдёт без подписи,
  а текст — следующим сообщением.
- Разметка: списки, `**жирный**`, `` `код` ``, ссылки `[текст](url)`.
  Длинный текст автоматически разбивается на несколько сообщений.
- Файлы с расширением `.md.example` бот не трогает — образец лежит в
  `content/telegram/queue/2026-11-10-example.md.example`.

Workflow **Telegram: отложенные посты** запускается при push поста в
очередь (в `master`). Job `wait` спит до ближайшего `publish_at` (не больше
5,5 ч за раз), затем `publish` публикует всё, чьё время наступило, переносит
файл в `content/telegram/sent/` коммитом `[skip ci]` и, если в очереди
остались посты, перезапускает workflow ждать следующий. Новый push в
очередь отменяет текущее ожидание и пересчитывает время. Точность — около
минуты (старт runner'а).

Cron (`'7 * * * *'`) — только страховка: GitHub запускает его раз в
несколько часов, поэтому раньше посты уходили с опозданием до 7 ч. Ручной
прогон: Actions → **Telegram: отложенные посты** → Run workflow (можно с
`dry_run` — тогда без ожидания). Проверить ожидание локально:
`python3 tools/telegram/bot.py queue-wait`.

Workflow делает коммит в текущую ветку. Если ветка защищена от push
бота, отправленные посты не будут помечены и уйдут повторно — разрешите
push для `github-actions[bot]` или публикуйте вручную.

## 8. Модерация обсуждения

Workflow **Telegram: модерация чата** раз в 10 минут забирает новые
сообщения через `getUpdates` (webhook не используется) и:

- удаляет сообщения, где больше 3 ссылок или есть шаблон спама
  («казино», «заработок», «криптовалюта», «ставки на спорт» и т. п.);
- после 2 нарушений за неделю ограничивает автора на 24 часа, после
  4 — блокирует;
- приветствует новых участников;
- отвечает на команды:
  - `/help` — список команд,
  - `/rules` — правила,
  - `/apk` — ссылка на последний релиз,
  - `/id` — ID чата (удобно для настройки).

Администраторы и автоматические пересылки постов канала не трогаются.
Правила и пороги меняются в `tools/telegram/moderation.json`
(`spam_patterns`, `max_links`, `mute_after`, `ban_after`, `mute_hours`,
`welcome`, `rules`, `help`).

Проверить без последствий: Actions → **Telegram: модерация чата** → Run
workflow, `dry_run` включён по умолчанию. В логе будет видно, кого и за что
бот удалил бы.

Ограничения:

- это не мгновенная модерация: спам может провисеть до ~10 минут;
- Telegram хранит обновления 24 часа — если Actions не запускался дольше,
  старые сообщения бот не увидит;
- GitHub отключает расписания после 60 дней без активности в репозитории —
  просто включите workflow снова;
- состояние (offset, нарушения) лежит в `actions/cache`; при сбросе кэша
  бот перечитает доступные обновления, повторные удаления безопасны.

## 9. Локальный запуск

Зависимостей нет:

```bash
export TG_BOT_TOKEN='1234567890:AA...'
export TG_CHANNEL_ID='@tenet_t7_dash'
export TG_DISCUSSION_CHAT_ID='-1001234567890'   # если нужна модерация

python3 tools/telegram/bot.py check
python3 tools/telegram/bot.py post-release --tag v1.8.1 --dry-run
python3 tools/telegram/bot.py run-queue --dry-run
python3 tools/telegram/bot.py moderate --dry-run
python3 tools/telegram/test_tools.py
```

## 10. Если не работает

| Симптом | Причина и решение |
| --- | --- |
| `chat not found` | Бот не добавлен в канал/группу или неверный ID. Для канала используйте `@username` |
| `not enough rights to send text messages` | Бот не администратор канала или нет права «Публикация сообщений» |
| `Conflict: can't use getUpdates method while webhook is active` | У бота остался webhook: `python3 tools/telegram/bot.py webhook --delete` |
| Модерация не видит сообщения | Бот не админ группы, включён privacy mode, или неверный `TG_DISCUSSION_CHAT_ID` |
| Анонс не пришёл, в логе `TG_BOT_TOKEN не задан` | Добавьте секрет `TG_BOT_TOKEN` в Settings → Secrets and variables → Actions |
| `no section for version` | Нет раздела `[X.Y]` в `CHANGELOG.md` и не удалось взять текст из GitHub Release |
| Пост опубликовался дважды | Перезапуск анонса вручную создаёт новый пост; удалите лишний в Telegram |

## Файлы

| Файл | Назначение |
| --- | --- |
| `tools/telegram/bot.py` | CLI: `post-release`, `run-queue`, `queue-wait`, `moderate`, `check`, `chat-id`, `chats`, `webhook` |
| `tools/telegram/tg.py` | клиент Bot API (stdlib, multipart для APK/фото) |
| `tools/telegram/markdown.py` | Markdown → HTML Telegram, лимиты и разбиение |
| `tools/telegram/releases.py` | раздел CHANGELOG, текст анонса, скачивание APK |
| `tools/telegram/postqueue.py` | очередь отложенных постов |
| `tools/telegram/moderation.py` | спам-фильтр, наказания, команды |
| `tools/telegram/moderation.json` | правила модерации и тексты |
| `tools/telegram/test_tools.py` | проверки без сети |
| `.github/workflows/telegram-post.yml` | анонс релиза (вызывается из `release.yml`) |
| `.github/workflows/telegram-queue.yml` | отложенные посты: ждёт `publish_at`, цепочка перезапусков |
| `.github/workflows/telegram-moderation.yml` | модерация, каждые 10 минут |
| `.github/workflows/telegram-check.yml` | ручная проверка настройки |
| `content/telegram/queue/` | очередь постов |
| `content/telegram/sent/` | уже опубликованные (переносит workflow) |

Токен хранится только в секрете GitHub Actions и передаётся боту через
переменные окружения. В репозиторий он не попадает.
